# Design: screen-lock

## Summary
Add a separate lock flag to the shared UI state, then route lock/unlock through the existing semantic gesture/state machine so the UI keeps rendering while the saver is suppressed. Provider pages reuse the existing chrome helper for the badge, while summary pages get a separate lock overlay in the shared summary chrome path.

## Requirements
- Lock starts with swipe down from the active stats UI.
- Lock does not stop stats refresh or rendering.
- Lock suppresses screensaver entry while active.
- Only swipe up unlocks while locked.
- Unlock restores the prior view and restarts the idle countdown immediately.
- Lock icon appears in the header chrome on provider pages and on the summary screen.
- No payload/data-model changes.

## Current State Analysis
The existing split already matches the feature boundaries: `ui.c` owns nav/input policy, `ui_screensaver.c` owns idle/saver transitions, and `ui_render.c` owns the visible chrome. The missing piece is a distinct lock flag and a render badge path that is independent from saver state.

### Key Discoveries
- `firmware/main/ui_internal.h:136-172` centralizes all shared UI state in `st`; it already has saver and saved-nav fields, but no lock bit.
- `firmware/main/ui.c:123-149` is the idle/saver gate and render loop; this is where lock suppression of saver entry belongs.
- `firmware/main/ui.c:251-309` is the only gesture/state-machine path; lock precedence over summary paging belongs here.
- `firmware/main/ui_screensaver.c:169-255` snapshots/restores nav state for saver mode; lock should not repurpose that lifecycle.
- `firmware/main/ui_render.c:494-541` is the shared provider chrome helper; `firmware/main/ui_render.c:1451-1543` is the separate summary chrome path.
- `firmware/main/touch.c:70-164` already emits swipe directions as semantic events, so no raw-touch changes are needed.

## Scope
### Building
- Add shared `locked` state in `st`.
- Make swipe-down enter lock globally in stats mode.
- Make swipe-up the only unlock gesture while locked.
- Block saver entry while locked without stopping stats refresh.
- Show a lock badge on provider pages and summary pages.

### Not Building
- Authentication, PINs, or persistence across reboot.
- Any payload/schema changes.
- Screensaver visual redesign beyond lock suppression.
- New touch primitives or raw gesture parsing changes.
- Changes to stats fetching or provider data shape.

## Decisions
### Separate lock bit
Use a distinct `locked` boolean in shared UI state rather than encoding lock into saver state. This preserves saver restore semantics and keeps lock as a simple gate on idle entry and input handling. Grounding: `firmware/main/ui_internal.h:136-172`, `firmware/main/ui_screensaver.c:169-255`.

### Lock wins globally
Treat swipe-down as lock entry anywhere in stats mode, including the summary list, so the requested gesture always works. This requires `ui_handle_input()` to branch on lock before summary paging. Grounding: `firmware/main/ui.c:251-309`, `firmware/main/touch.c:70-164`.

### Shared chrome plus summary overlay
Reuse `render_page_chrome()` for provider-page badges and add a separate summary-chrome badge path for the footer/top band. This follows the existing render split instead of forcing summary into the provider helper. Grounding: `firmware/main/ui_render.c:494-541`, `firmware/main/ui_render.c:1451-1543`.

## Desired End State
- `ui_handle_input()` treats swipe-down as lock entry when unlocked, and swipe-up as unlock when locked.
- `ui_task()` continues to refresh stats and render on dirty state while locked.
- `saver_enter_locked()` refuses to activate saver mode while the lock is active.
- Provider cards show a lock badge via shared page chrome.
- Summary view shows the lock badge in its own chrome path.

## Ordering Constraints
- Add the shared lock state first so all other files can read it consistently.
- Gate gesture handling before summary paging so swipe-down becomes lock entry.
- Gate saver entry before any saver transition logic.
- Add provider badge rendering and summary badge rendering after the state exists.
- Keep render/update cadence independent from lock state.
